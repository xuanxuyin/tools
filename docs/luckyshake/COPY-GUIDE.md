## 二、表述原则（zh & EN 通用精神）

1. **言简意赅**：按钮 = 动作本身（领取 / 抽签 / 摇一摇球），不加数字、不加解释；同一状态全界面只出现**一处**（倒计时只在按钮上，不再有侧行"下一枚 mm:ss"——2026-11-13 👤 定）。
2. **机制词→仪式词**：向用户解释规则时用仪式语汇（加抽→续缘、全站累计→十方功德、每日重置→明日缘再至），机制透明留给 FAQ。
3. **营销段不自我拆台、不带披露词**：不出现"人写 / 我们编 / 判词是人写"类表述；披露（**手写、随机、免费、无需注册、本地存储**）只放 FAQ 直问处与 fine print——营销位（chips / hero / 卡片 desc / feature 栏 / meta description）零披露词，2026-11-13 👤 "手写不用告诉用户吧，感觉特别 AI"（先例：筒中百签皆手写·每日一次免费机缘·无需注册 → 筒中百签 · 一日一缘）。
4. **FAQ 问句正向或中性**（2026-11-13 👤 "这种问题有点反向或者让人反感"）：禁反向预设（为什么…**才**…：为什么抽完才让我选题 → 抽完签才选题，有什么讲究）、禁质疑腔（**真是**五五开 / **真能**预言 / 是**真·**经典 / 这些签文是**认真的吗** / 为什么**还要**抛硬币 → 改好奇向或益处向）。答案语气可直可诚，问句不许先立一个抱怨。
5. **不教训用户**（2026-11-13 👤 "想好了，有点在强行教别人的情绪"）：结尾邀约不用祈使评价（~~想好了，再摇一次~~ → 想再问时，签筒还在）；EN 同理不用否定祈使开头（~~You don't pick…~~ → Let the jar do the picking）。
6. **标点**：短标签（按钮 / 标题 / 栏头 / chip）**不带句号**；zh 引号一律**「」**；数字用阿拉伯（8 点、24、0–9）。
7. **物件层例外**：印章 / 签纸 / 8 号球字盘 / 铜币刻字的重字重（≥800）与宽字距是材质表达，不受 UI 收敛规则约束（unslop 白名单）。
